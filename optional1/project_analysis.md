# 完成版项目与选做1的衔接分析

本次基线为用户2026年10月20日提供的项目ZIP，与远程main提交`533b87dd1225d6bd11cb8bdc98b0f2f91eb69617`的706个文件一致。四份必做任务书位于`docs/assignments/`，可以从项目内部直接追溯要求。分析重点是如何复用主体材料完成选做1，不改变其他成员的主体成果。

## 四个必做工作包的输入输出关系

| 工作包 | 本版已有材料 | 对选做1的作用 |
| --- | --- | --- |
| 1 代码预处理与数据标准化 | 14父样本、26代码片段、17输入包、来源和行号映射、候选标签、抽查记录 | 固定样本与模型输入；片段与父样本不得混计 |
| 2 Prompt提示词工程 | v1/v2/final模板、四类规则、输出协议、42条独立上下文历史响应 | 提供基线与增强版；保存所有失败，不只取合规输出 |
| 3 LLM漏洞推理逻辑 | 三级推理框架、判定矩阵、正反例与边界案例、一致性说明 | 定义何种证据能支持候选、确认和排除 |
| 4 POC验证与结果优化 | 环境、17条条件记录、14父标签、脱敏证据、适配差异、反馈变更及两轮修正版 | 提供金标准依据与基于实测的最终Prompt |

总体链路为：标准代码输入 → Prompt → 模型响应 → 人工适配验证 → 标签与反馈 → Prompt修订。本版已经具备这条主体链路的归档材料，不能继续使用旧工作区“42条全部not_run”的判断。

## 可以直接复用的部分

三版原始输入输出、工作包4条件标签、静态协议检查器、反馈变更记录和修正版Prompt可以直接纳入选做1。此次新增离线统计器从这些源文件重算结果，不复制原报告中的百分比充当计算。

主比较选取原v1、原v2及实测反馈修正版final-wp4-v2。原final及工作包4中间轮也保留，防止只挑最好的一轮；六组共84份响应，但仍只有14个不同父样本，不能写成84个独立测试样本。

## 主体完成与选做验收的区别

工作包4允许对POC补齐环境并记录适配，因此人工适配脚本的实测可以支持主体漏洞标签。但是选做1比较“不同版本生成POC的可运行率”，必须分别追踪每个版本原稿，不能让同一套人工参考脚本为三版重复计功。

当前源文件明确将模型POC记录为未运行，历史时延和采样参数也未完整保留。新增报告已经提供可核验指标、图表、版本溯源和补测台账；这些历史缺项必须如实列为未测，不能通过整理文件补成实验事实。
