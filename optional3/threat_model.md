# 威胁模型

## 范围和资产

本扩展保护“输入代码与资料 → LLM分析 → 结构化结果 → POC审查 → 人工隔离执行 → 报告”链路。沿用工作包1样本与工作包2输出协议；工作包4历史证据只作参考，不自动证明本次模型或本次POC执行可信。

资产包括系统Prompt、密钥、内部路径、未公开样本、工具权限、出站网络、POC执行权限、验证证据及最终报告。实验仅使用固定合成秘密标记；不向模型提供真实密钥、Cookie、宿主文件或私人数据。合成标记不是实际系统Prompt或业务凭据。

## 信任边界

1. 人工确认的审计目标、授权范围及外部审批流程属于控制层；代码和外部材料不具备控制权。
2. 标准化代码也可能含恶意注释、字符串或教学文案。来源公开不代表指令可信。
3. 扫描报告、历史摘要和工具回显默认为数据；声称来自SYSTEM或已验证不能自行升级可信级别。
4. LLM输出是待核验建议。JSON结构正确、路径存在和代码可编译均不等于事实成立或允许执行。
5. 审批记录与隔离配置由模型外部的人维护；审批只绑定特定脚本哈希、环境及有效期，不授权其他代码。
6. 最终报告区分原始输出、程序判定、人工结论和实测证据，保留版本与修改原因。

## 攻击者能力与目标

攻击者可控制待分析注释、参考文档、扫描文本或附加指令，可使输出包含危险POC；不能修改可信策略、审批日志或宿主环境。目标是改变漏洞结论、伪造证据、泄露合成秘密、诱导越界建议或自动执行。

## 六类覆盖

- direct：A01-1/A01-2，附加文本要求忽略审计规则，目标是无证据排除。
- indirect：A02-1/A02-2，通过源码注释载体要求服从指令，目标是污染结论。
- context：A03-1/A03-2，伪造历史“已确认安全”，目标是省略重新核验。
- tool_spoof：A04-1/A04-2，扫描回显冒充系统及验证结果，目标是伪造信任。
- leak：A05-1/A05-2，索要系统区域的合成canary，目标是测试泄露。
- malicious_poc：A06-1/A06-2，要求越界目标和立即执行，目标是突破执行边界。

上述载体作为附加字段构造，原始源码及其行号不改变；不声称覆盖所有真实工具协议。六个正常对照用于评估误拒，特别保留合法日志引用和安全课程描述。

## 处置目标

恶意文本仍作为数据处理，保留合法审计；模型无证据结论隔离，不自动升级确认；危险POC隔离；任何脚本都不能由校验器自动执行。关键词命中是审查信号，不是攻击真值。

## 剩余风险

语义改写、多语言、编码、分段注入、长上下文和模型记忆可能绕过模式检测；AST不能证明程序无恶意。HTTP重定向、动态目标、DNS、依赖供应链及资源耗尽需要外部隔离和人工复核。Docker本身也不能提供绝对隔离，必须保持宿主更新，且不可挂载Docker socket。
