# AUTH-001 用户资料更新权限分析

## 样本信息

- 父样本编号：AUTH-001
- 分析文件：workpackage1/normalized_samples/AUTH-001/E.php及F.php
- 业务要求：只有admin可以修改全部用户资料
- 当前状态：静态分析，未运行POC
- 分析范围：更新接口

## 语法检测

E.php先检查安全配置与当前用户名，仅当配置为impossible且用户不是admin时返回Access denied并退出。

随后检查请求方法是否为POST，读取请求体并解析JSON。从请求中取得id、first_name和surname，用于构造UPDATE语句，修改指定user_id对应的用户资料。

F.php提供身份与配置获取函数：用户名来自服务器会话，安全配置优先取自客户端security Cookie。

处理流程：获取安全配置与当前身份 → 条件授权检查 → POST方法检查 → 读取并解析请求JSON → 使用目标用户id与修改内容构造UPDATE → 数据库执行 → JSON结果响应。

## 漏洞语义识别

目标用户id由请求提供，当前接口未见将该id绑定到当前用户或逐对象授权的检查。

仅在impossible配置下检查管理员身份。在low、medium及high配置下，非管理员不会被这条角色检查拦截，存在修改其他用户资料的候选路径。

POST检查只限制请求方法；JSON解析检查只处理输入格式。二者均不能证明请求者有权修改目标对象。

条件案例：

- 正例候选：普通用户在low、medium或high配置下，提交指向其他专用测试用户的更新请求，可能触发未授权修改。
- 防护反例：配置实际解析为impossible且当前用户非admin时，接口在执行更新前拒绝请求。

由于安全配置优先读取客户端Cookie，特定配置下的拒绝行为不能证明整个接口始终受保护。

## 业务安全风险判定

若普通用户可以修改其他用户的姓名字段，则违反仅admin可修改全部用户资料的业务要求。

读取接口与更新接口的授权条件不同：high配置下读取接口拒绝非管理员，但更新接口中的角色检查不会拒绝。这说明不能用页面或读取接口的保护，推断更新接口也受到同样保护。

还需核查包含文件的认证初始化、实际会话、接口可达性及数据库执行条件，暂不对匿名访问作确定结论。

## 初步结论与验证要求

静态判断：存在依赖安全配置的越权更新候选。

结论状态：待验证。

后续仅在授权本地靶场使用专用测试账号和对象验证。记录目标原值，以普通用户会话提交无害测试标记，再通过可信的独立读取方式核查目标数据是否改变，最后恢复原值。

成功确认需要证明：修改由低权限请求触发，目标不属于其授权范围，且数据确实发生变化。HTTP 200或result为ok不能单独证明更新成功。

impossible条件下应验证请求被拒绝且目标数据未改变。条件案例归属AUTH-001父样本，不新增独立样本计数。

## 范围外风险

UPDATE语句直接拼接请求字段，还存在需要单独审计的SQL注入线索。本案例聚焦权限越权，不将该线索混入权限漏洞的判定与统计。

## 代码位置与引文补充

以下行号采用工作包1标准化片段的局部行号。

### 更新接口的授权条件

片段AUTH-001-E，第11行：

```php
if (dvwaSecurityLevelGet() == "impossible" && dvwaCurrentUser() != "admin") {
```

第12至13行返回Access denied并退出。该检查只在impossible配置下拒绝非admin，不覆盖high等其他配置。

### 请求方法与输入来源

片段AUTH-001-E，第16行：

```php
if ($_SERVER['REQUEST_METHOD'] != "POST") {
```

该条件只限制请求方法，不检查请求者是否有修改权限。

第26至27行：

```php
$json = file_get_contents('php://input');
$data = json_decode($json);
```

目标id及修改内容来自请求体。成功解析JSON不等于通过授权检查，也不等于字段已经完整验证。

### 修改目标与数据库操作

片段AUTH-001-E，第47行：

```php
$query = "UPDATE users SET first_name = '" . $data->first_name . "', last_name = '" .  $data->surname . "' where user_id = " . $data->id . "";
```

修改对象由请求中的id决定，当前路径未见将目标对象绑定到当前用户的检查。第48行调用mysqli_query执行更新。

第50行：

```php
print json_encode (array ("result" => "ok"));
```

该响应不能单独证明目标记录已经改变，仍需独立回查实际数据。

### 身份与配置来源

片段AUTH-001-F，第26行从会话取得用户名：

```php
return ( isset( $dvwaSession[ 'username' ]) ? $dvwaSession[ 'username' ] : 'Unknown') ;
```

第32至34行优先读取客户端配置：

```php
if (isset($_COOKIE['security'])) {
	return $_COOKIE[ 'security' ];
}
```

因此，授权条件依赖客户端可影响的配置值；但当前尚未完成接口外围认证初始化的核查。

## 静态证据等级

证据等级：medium。

依据：请求输入、角色检查、更新目标、数据库执行及身份和配置来源均可定位；但接口外围认证、实际会话与部署条件尚未完整核查。因此保留越权更新候选，结论为待验证。

本等级表示静态证据完整程度，不代表漏洞概率或风险严重程度。

## 风险优先级

核验优先级：P1，优先核验。

理由：修改目标id来自请求，当前接口仅在impossible配置下拒绝非admin。若普通用户能够修改其他用户资料，将违反仅admin可修改全部用户资料的业务要求。

当前证据等级仍为medium，结论仍为待验证。P1表示核验顺序，不表示漏洞已确认。

优先补充：

1. 接口外围认证、实际会话身份及安全配置。
2. low、medium、high与impossible条件下的授权行为。
3. 普通用户能否修改其授权范围之外的专用测试对象。
4. 数据是否真实改变，而非仅返回result为ok。

验证前记录专用测试对象的原值，提交无害标记后通过可信的独立路径回查，并恢复原值。不得以真实用户资料作为修改对象。

后续根据实际可达性、可修改范围和业务影响重新评估修复优先级。
