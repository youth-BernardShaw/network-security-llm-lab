# AUTH-001 用户资料读取权限分析

## 样本信息

- 父样本编号：AUTH-001
- 分析文件：workpackage1/normalized_samples/AUTH-001/D.php及F.php
- 业务要求：只有admin可以读取全部用户资料
- 当前状态：静态分析，未运行POC
- 分析范围：读取接口，不包含更新接口

## 语法检测

D.php调用dvwaSecurityLevelGet获取安全配置，并调用dvwaCurrentUser获取当前用户名。

仅当配置为high或impossible，且当前用户不是admin时，接口返回Access denied并退出。其余情况下，代码继续查询users表中的user_id、first_name和last_name，并将结果作为JSON返回。

F.php中，dvwaCurrentUser从服务器会话读取用户名；dvwaSecurityLevelGet优先读取客户端security Cookie，未提供该Cookie时再按认证配置选择默认值。

数据流：请求及会话 → 获取配置与身份 → 条件授权检查 → 查询全部用户资料 → JSON响应。

## 漏洞语义识别

业务要求为仅admin可以读取全部用户资料，但D.php只在high或impossible配置下拒绝非管理员。

F.php表明安全配置优先取自客户端Cookie。因此，该授权条件依赖客户端可影响的配置值，存在普通用户在其他配置下绕过管理员限制的候选路径。

需要区分两个条件案例：

- 正例候选：普通用户在low或medium配置下访问读取接口，D.php中的管理员检查不会拦截，存在读取全部用户资料的候选。
- 防护反例：在实际解析结果为high或impossible且当前用户非admin的条件下，D.php明确返回拒绝并退出，该条件下的读取路径受到保护。

反例仅说明特定条件下的拒绝行为，不能据此认定整个接口安全，因为配置来源本身可受客户端影响。

## 业务安全风险判定

若普通用户能够访问该独立接口并取得其他用户资料，则违反仅admin可读取全部资料的业务要求。

F.php定义了认证检查函数，但不能据此认定D.php已经执行该检查。还需核查被包含文件的初始化行为、接口访问条件及实际会话状态。当前不对匿名访问作确定结论。

D.php中的htmlspecialchars属于输出编码，不代替角色授权，也不能阻止未授权的数据读取。

## 初步结论与验证要求

静态判断：存在依赖安全配置的越权读取候选。

结论状态：待验证。

后续使用授权本地靶场的专用普通用户会话，在相同接口和不同配置下进行请求对照，同时记录服务器实际解析的配置、身份及响应。

成功确认需要证明普通用户实际取得按业务要求仅允许管理员读取的数据。HTTP 200或JSON响应本身不构成充分证据。

high或impossible条件下应检查是否拒绝并且未返回受保护数据。所有条件案例仍归属AUTH-001父样本，不计为新增独立样本。

## 代码位置与引文补充

以下行号采用工作包1标准化片段的局部行号。

### 读取接口的授权条件

片段AUTH-001-D，第10行：

```php
if ((dvwaSecurityLevelGet() == "high" || dvwaSecurityLevelGet() == "impossible") && dvwaCurrentUser() != "admin") {
```

第11至12行返回Access denied并退出，说明该拒绝分支只在指定配置及非admin条件同时满足时触发。

### 数据查询与返回

片段AUTH-001-D，第15行：

```php
$query  = "SELECT user_id, first_name, last_name FROM users";
```

第16行执行查询，第40行返回结果：

```php
print json_encode ($users);
```

查询中未按当前用户限制记录范围，因此需要核查调用者是否具有读取全部用户资料的权限。

### 身份来源

片段AUTH-001-F，第26行：

```php
return ( isset( $dvwaSession[ 'username' ]) ? $dvwaSession[ 'username' ] : 'Unknown') ;
```

当前用户名来自会话。该函数本身不证明读取接口已执行登录认证。

### 配置来源

片段AUTH-001-F，第32至34行：

```php
if (isset($_COOKIE['security'])) {
	return $_COOKIE[ 'security' ];
}
```

配置优先读取客户端Cookie，说明授权条件依赖客户端可影响的值。

## 静态证据等级

证据等级：medium。

依据：角色检查、全部用户查询、结果返回及身份和配置来源均可定位；但接口外围初始化、实际认证与部署条件尚未完整核查。因此保留越权读取候选，结论为待验证。

本等级反映静态证据完整程度，不代表漏洞概率或影响严重程度。

## 风险优先级

核验优先级：P1，优先核验。

理由：接口查询全部用户资料，但管理员检查只覆盖部分配置，且配置优先取自客户端Cookie。若普通用户能够通过该路径取得受保护资料，将违反仅admin可读取全部用户资料的业务要求。

当前证据等级仍为medium，结论仍为待验证。P1表示核验顺序，不表示漏洞已确认。

优先补充：

1. 接口外围初始化和登录认证是否实际执行。
2. 普通用户会话下，服务器实际解析的身份与安全配置。
3. low、medium与high、impossible条件下的响应差异。
4. 普通用户是否取得按业务要求不应读取的专用测试用户资料。

验证应使用相同接口和受控条件对照，不能以管理员请求成功或HTTP 200单独确认越权。

后续根据接口可达性、数据敏感性和实际暴露范围重新评估修复优先级。
